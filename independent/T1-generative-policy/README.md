# T1: Why do flow policies beat Gaussians in online RL? A controlled decomposition

**Question.** FPO/FPO++, FFM, TruDi, GoRL and QF3 each credit a different mechanism for flow/diffusion policies beating Gaussians on humanoid tasks (correlated exploration, temporal correlation, iterative computation, multimodality, the surrogate itself). Which one is it, and does a Gaussian head with that one mechanism close the gap?

**Status.** Laptop pilot run 14 Oct 2026 (3 seeds). Verdict: `KILL TEST: INCONCLUSIVE`: the point-mass tasks do not reproduce the humanoid gap on average; flows and the GMM head were more *reliable* across seeds on the bimodal task. Read `notes/pilot_notes.md` before touching anything. The paper-grade version needs MJX humanoids on a GPU. No paper draft yet.

## Layout

| folder | contents |
|---|---|
| `code/` | `t1_policy_heads.py` (one PPO trainer, eight policy heads); `code/lib/control_tasks.py` has the Reach / Fork / Corridor tasks |
| `data/` | empty: tasks are generated by code |
| `results/` | `runs.csv` (one row per run), `summary.csv`, `verdict.txt` |
| `logs/` | `pilot.log` |
| `notes/` | `pilot_notes.md`: results table, interpretation, what to fix (the `flowfrozen` head is broken) |
| `paper/` | empty |

## Run

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python code/t1_policy_heads.py --smoke         # minutes
.venv/bin/python code/t1_policy_heads.py                 # pilot grid, ~1 h on an M1 Pro
.venv/bin/python code/t1_policy_heads.py --resume        # skip runs already in results/runs.csv
.venv/bin/python code/t1_policy_heads.py --summarize     # recompute summary/verdict only
.venv/bin/python code/t1_policy_heads.py --full --device cuda
```
