# R1: Look less, act later. Off-policy evaluation when the policy chooses *when to check*

**Question.** ICU logs are irregular because clinicians decide when to look and when to act. Frost et al. (2602.06603) show that binning those logs to a fixed grid makes FQE overestimate deployed value 1.5–3x; Insulin4RL (2606.19481) keeps raw timing but treats it as exogenous; EDQ (ICLR 2025) evaluates treatment timing but excludes the observation process. Can we evaluate, from such logs, a policy that chooses both the dose and the time of the next check, and does the "mask the extra checks" identification trick from epidemiology (Robins, Orellana & Rotnitzky 2008; Caniglia et al. 2019) carry over to SMDP Q-evaluation?

**Status.** Laptop pilot run 15 Oct 2026 (CPU, tabular FQE on a synthetic continuous-time glucose simulator), two loggers. Verdict: `KILL TEST: KILLED` under both (`results/verdict.txt`, `results/protocol/verdict.txt`): the masking/IPW identification trick did not help and the support flag did not separate sparse from dense. What survived: binning is miscalibrated with a Δ-dependent sign flip; treating timing as exogenous breaks when the target checks more often (−4.0) and an SMDP (dose, wait) FQE fixes it (−1.0) when the logger's timing varies; evaluating sparser monitoring from protocol-driven logs is not identified in practice. Read `notes/pilot_notes.md` before touching anything. Recommendation: fold the binning result into R3; keep the SMDP-FQE fix as a short clinical paper if it holds on Frost's UVA/Padova simulator (`github.com/tdgfrost/temporal-resampling-experiments`, MIT) and Insulin4RL.

## Pre-registered kill test (written before the pilot ran)

Targets: `mode` (clinician's modal rule), `sparse` (one wait class longer), `dense` (one wait class shorter), `dosehi`, `doselo`. Estimators: `bin1h`, `bin4h` (fixed-grid FQE), `exo` (raw timing, dose-only action), `timing` (action = dose × wait, γ^τ), `timing+mask` (compound transitions over zero-dose checks, unweighted), `timing+ipw` (same, inverse-probability weighted for the logger's "keep waiting" decisions).

- **K1.** On `sparse`, mean |bias| of `timing+ipw` is less than half that of the better of `bin1h` / `exo`, and this holds in at least 80% of seeds.
- **K2.** The support diagnostic (weight of target look-ups that land on unvisited state-actions) is at least 3x larger for `dense` than for `sparse` under `timing+ipw`. This is the identifiability asymmetry showing up as a measurable flag.
- **K3.** (secondary) Binned FQE estimates sit closer to the true value of the *fixed-grid* policy (dose rule applied every Δ, paying every check) than to the true value of the target, for at least half of the (target, Δ) pairs. This is the "binning silently evaluates a degenerate timing policy" claim.

SUPPORTED if K1 and K2 hold. INCONCLUSIVE if exactly one holds. KILLED if neither.

## Run

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python code/r1_timing_ope.py --smoke        # ~5 s
.venv/bin/python code/r1_timing_ope.py                # pilot: 5 seeds × 3000 patients, ~15 min on an M1 Pro
.venv/bin/python code/r1_timing_ope.py --eps-wait 0.02 --tag protocol   # near-protocol logger
.venv/bin/python code/r1_timing_ope.py --resume       # skip finished rows
.venv/bin/python code/r1_timing_ope.py --summarize    # recompute summary/verdict from results/
.venv/bin/python code/r1_timing_ope.py --full         # 20 seeds × 10000 patients
```
